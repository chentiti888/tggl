# tggl · Telegram 机器人一键部署脚本

交互式部署 Telegram 机器人：**获取代码 → 安装环境 → 写入 Token / 用户ID → 开机自启**，全程在菜单里选择或输入，不用再手敲命令、手改脚本、手写服务文件。

脚本没有任何预设值，机器人名称、安装目录、仓库地址、变量名、Token、用户ID 都由你现场输入。不使用虚拟环境，依赖直接装到系统 `python3`。

## 一条命令使用

在服务器上以 root 运行：

```bash
bash <(curl -fsSL -H 'Cache-Control: no-cache' "https://raw.githubusercontent.com/chentiti888/tggl/main/tg-bot-gl.sh?t=$(date +%s)")
```

> 命令里的 `?t=$(date +%s)` 和 `Cache-Control` 是为了避免 GitHub 缓存拿到旧版本，更新脚本后尤其有用。

也可以在命令末尾直接带上机器人仓库地址，新增机器人时就不用再输入：

```bash
bash <(curl -fsSL -H 'Cache-Control: no-cache' "https://raw.githubusercontent.com/chentiti888/tggl/main/tg-bot-gl.sh?t=$(date +%s)") https://github.com/用户/机器人仓库.git
```

## 要求

- Linux 服务器，root 权限
- systemd（用于开机自启）
- 能访问 GitHub（仓库拉取模式需要）
- 自动适配 apt / dnf / yum 安装 git、python3、pip

## 快速开始

1. 运行上面的命令，首次进入会提示 **新增机器人**。
2. 输入机器人名称（同时用作服务名，仅限小写字母、数字、`-`、`_`）。
3. 输入安装目录，例如 `/root/mybot`（不能直接用 `/root`、`/opt` 等系统目录，请用其下的子目录）。
4. 选择代码来源：
   - **从 GitHub 仓库拉取**：输入仓库地址和分支（分支留空为默认分支）。
   - **本地上传**：脚本会创建目录，你自己把机器人代码传进去。
5. 进入主菜单，选 **6) 一键部署**，按提示输入 Token 和用户ID，最后自动创建并启动开机自启服务。

## 主菜单

| 选项 | 作用 |
| --- | --- |
| 1) 拉取 / 更新仓库 | 克隆或更新机器人仓库；本地上传模式下可在此补填仓库地址 |
| 2) 安装环境 | 可选安装额外系统包；安装 python3 / pip；有 `requirements.txt` 就自动安装，没有就让你手输 pip 包 |
| 3) 写入密钥 / 用户ID | 把 Token、用户ID 写进机器人脚本或 `.env` 文件 |
| 4) 服务管理（开机自启） | 创建、启动、停止、重启服务，查看状态和日志，删除服务，重新选择主程序 |
| 5) 查看当前状态 | 显示来源、目录、主程序、Python 路径、版本、服务状态 |
| 6) 一键部署 | 依次执行 获取代码 → 安装环境 → 写入密钥 → 创建服务并启动 |
| 7) 卸载 | 停止并删除服务，可选删除安装目录和从机器人列表移除 |
| 8) 切换 / 新增机器人 | 同一台服务器可管理多个机器人 |

## 写入 Token 和用户ID

进入菜单 3 后，先选择写入位置：

### 方式一：写入 py 脚本里的变量

直接修改机器人代码里的赋值语句，如 `BOT_TOKEN = '...'`。

- 先选择要写入的 py 文件，脚本会列出检测到的 token / admin / owner 等相关变量名供你参考。
- 变量名由你输入。变量已存在就替换；不存在就在 `import` 之后新增。
- 用户ID 会自动适配原有格式：原来是列表就写成 `[1, 2]`，元组、集合同理，原来是单个数字则只接受一个 ID。
- 写入前自动备份为 `文件名.bak`，写入后做语法检查，失败自动还原。
- 如果变量是通过 `os.getenv` / `os.environ` 读取的，会提示改用 `.env` 方式。

### 方式二：写入 .env 文件（推荐）

写入 `安装目录/.env`，格式为 `KEY=value`，权限 600。

- 机器人代码需要用 `os.environ` / `os.getenv` 读取。
- systemd 服务会自动加载这个 `.env`。
- 用户ID 以逗号分隔写入，如 `ADMIN_IDS=111,222`，代码里自行解析。
- 好处是密钥不进代码，仓库更新时不会冲突。

### 输入说明

- Token 输入时不显示，写入前只显示打码后的内容，格式不标准时会提示确认。
- 用户ID 支持空格或逗号分隔，必须是数字。
- 也可以用「自定义变量」写入任意字符串或数字类变量。

## 开机自启

菜单 4 → 1 会生成 `/etc/systemd/system/<机器人名称>.service`：

- 工作目录为安装目录
- 使用系统 `python3 -u 主程序` 运行
- 自动加载安装目录下的 `.env`（有则加载）
- 异常退出 5 秒后自动重启
- 创建后立即启动，并设置开机自启

常用查看命令：

```bash
systemctl status 机器人名称
journalctl -u 机器人名称 -f
```

## 多个机器人

每个机器人有独立的目录、服务和配置，互不影响。脚本启动时会列出已有机器人，选编号进入管理，或输入 `n` 新增。配置保存在 `/etc/tgbot-installer/<名称>.conf`，权限 600。

## 更新机器人代码

菜单 1 会对已有仓库执行更新。如果本地有修改（比如已把密钥写进了 py 文件），会先 `git stash` 暂存，更新完再恢复；恢复冲突时会提示，修改仍保留在 stash 里。更新完成后到服务管理里选「重启」即可生效。长期使用建议用 `.env` 方式保存密钥，避免此类冲突。

## 注意事项

- 依赖直接安装到系统 Python。遇到系统限制（PEP 668）时，脚本会自动加 `--break-system-packages` 重试。
- 安装目录不能是 `/`、`/root`、`/home`、`/opt`、`/etc`、`/usr`、`/var` 等系统目录，卸载删除目录时也会拒绝。
- 卸载时删除安装目录需要输入 `yes` 确认，目录内的代码和密钥会一并删除。
- 机器人名称同时是服务名，请避免与已有服务重名。
- 私有仓库拉取需要自行解决认证（如使用带权限的访问地址或配置 SSH 密钥）。

## 常见问题

**运行后看到的是旧版本？**
GitHub 的 raw 链接有缓存，使用上面带时间戳和 `Cache-Control` 的命令即可。

**提示 404？**
检查仓库名、分支名（默认 `main`）和文件名 `tg-bot-gl.sh` 是否与链接一致。

**机器人启动失败？**
菜单 4 → 6 查看最近日志，常见原因是依赖没装全、Token 变量没写进去，或主程序选错了（菜单 4 → 9 可重新选择）。

**同一台服务器想再装一个机器人？**
重新运行脚本，选 `n` 新增即可。
